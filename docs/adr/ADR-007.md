title: Privacy-safe logging and email data minimisation
kind: cross-cutting
context: "REQ-012 requires the customer's email address to be stored only where needed\
  \ and never written to logs. The address enters through CreateOrderRequest, travels\
  \ in the confirmed, rejected and cancelled event payloads, and is needed only to\
  \ send emails. EmailSentPayload already omits it."
decision: "Apply a shared logging convention and library: structured JSON logging\
  \ with a masking filter that redacts email patterns, DTOs that exclude customerEmail\
  \ from toString, and request/response body logging disabled. Only Order Management\
  \ and the transient send step in Order Notifications hold the address, and Inventory\
  \ never receives it."
alternatives:
- option: Rely on developer discipline and code review
  rejected_because: "Error-prone and unverifiable, one slip leaks personal data into\
    \ logs."
- option: Encrypt email addresses in all services
  rejected_because: Does not meet the goal of storing only where needed and adds key
    management for little gain when minimisation is possible.
consequences: Leaks are prevented even by accident and log tests can check for them.
  Debugging relies on orderId correlation rather than email. A small shared logging
  module is needed.
